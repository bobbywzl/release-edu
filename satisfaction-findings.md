# Tree EDU — Satisfaction & Progress Audit: Definitive Synthesis

*39 code-verified findings from 7 lenses, merged to 27. All paths relative to `/home/user/release-edu/`. ~25 load-bearing citations were re-verified against the repo during synthesis; every one checked out — no corrections were needed.*

## 1. Executive read

Tree EDU's progress-feeling is strongest exactly where its laws demand it: the in-workspace verification loop — syllabus-coverage checkpoints, hypercorrection, persisted remediation debt, growth-gated completion — is honest and mechanically excellent, and a complete celebration engine (74-title rank ladder, overlays and fanfares, streak accelerator, badge catalog) already exists to pay it off. The biggest leak is that almost none of that payoff fires where learning happens: badge evaluation, the daily-goal ring, streak state, personal records, and level identity live only on the dashboard home (and a portfolio visit permanently swallows badge unlocks), so the workspace — where 100% of learning XP is earned — celebrates late, elsewhere, or never. The second leak is inverted magnitude plus a handful of honesty cracks: a week of check-ins (500 XP) out-pays and out-ceremonies mastering an entire tree (~113 XP), while the sidebar ships a wrong level formula, wrong answers play the win chime, badge copy calls total XP "verified learning," and the portfolio renders a consistency score that is just streak×7.

## Completeness critic

Three material gaps, all verified against the repo.

**1. The Review loop is an uncapped, full-pay XP faucet — the audit's economy lens (item 6) missed the actual farming vector, and item 12's fix would widen it.** The product's anti-grinding economics is deliberate: correct answers on verified nodes pay ~25% (`src/app/api/tree/[id]/node/[nodeId]/quiz/route.ts:403` — `isVerifiedNode && !isReview ? baseDifficulty * 0.25 : baseDifficulty`), but reviews are explicitly exempted ("reviews must stay worth it", `:18-20`) and `/api/tree/[id]/review/route.ts` has no minimum-staleness gate whatsoever — it just sorts verified nodes by `reviewedAt` ascending and always returns a target. So Maya (the report's own XP-grinder persona) can round-robin the Review button on a completed tree for full `quiz_correct` per one-question click, immediately and forever, re-stamping `reviewedAt` each pass with no cooldown, cap, or diminishing return — resurrecting exactly the exploit the 25% discount was built to kill, and farming the same xp_* badge ladder item 6 already calls a "false claim on a résumé surface." Item 6 audits check-in inflation in detail but never this; worse, item 12's proposed fix (due-review chips, extending review to active trees) widens the faucet without a spacing gate — the audit recommends amplifying an unpriced loop it never priced.

**2. A hidden global streak multiplier makes every learning payout illegible — no item among 27 mentions it, and item 6's own arithmetic is quietly wrong because of it.** `getStreakMultiplier` = `1.0 + min(streak/100, 0.5)` is applied to ALL XP sources except the two streak payouts (`src/lib/xp-engine.ts:93-95, 317-322`), and a grep across `xp-panel.tsx`, `xp-toast.tsx`, and `i18n.tsx` finds zero UI string naming any multiplier — the engine's own comment concedes the principle ("legibility beats a hidden multiplier") but applies it only to the exempted streak payouts. Consequences the audit never counts: identical acts pay visibly different amounts day to day (+15 vs +19 vs +22) with no explanation on any toast; a streak break silently devalues every future payout by up to a third — a second, uncounted loss stacked underneath item 3's loss moment; and the report's load-bearing numbers ("objective_mastered flat 20," "Tree Mastered ≈113") hold only at streak≈0, so its headline attendance-vs-mastery ratios shift for exactly the long-streak users items 3/13 obsess over. For an audit whose central lens is reward honesty/legibility (items 6, 9, 17), an invisible 1.0-1.5x scalar on the entire economy is a first-order omission.

**3. The insight constellation — the product's self-declared moat — received zero coverage across all 7 lenses, and its gathering loop is precisely the "tracked silently, celebrated never" pattern the audit indicts everywhere else.** Insights are created/reinforced server-side during workspace chat (`src/app/api/tree/[id]/node/[nodeId]/chat/route.ts:419-436`) with no stream marker (only `[[TREE_SUGGEST]]`/`[[XP]]`/`[[QUIZ]]` exist), the workspace contains no insight UI at all (grep empty), and the only surfaces are dashboard-home's "Bob's week with you" digest and a collapsed "N insights" counter (`src/app/dashboard/page.tsx:130-141, 227-241`) — so the moment Bob learns something about you, the core personalization-as-progress feeling, is never signaled where it happens, star-count growth is never acknowledged, and a learner who lives in the workspace never sees the open learner model that CLAUDE.md's cited research says improves learning by being legible. The audit built its top findings on this exact pattern (badges item 2, origin item 15, build log item 16, records item 20) yet never pointed the same instrument at the asset the project documentation ranks first — mechanically, verification writes `knowledge` insights (`tree-engine.ts:1621-1635`, cited in item 4) and no item asks whether the learner ever watches their constellation grow.
